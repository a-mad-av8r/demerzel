Demerzel is a local-first LLM gateway: one OpenAI/Anthropic-compatible endpoint on
your laptop, with a pool of accounts behind every provider — several Claude or Codex
subscriptions, API-key collections, cloud providers — with deterministic serial
failover between them. Everything below answers three questions: what we borrow from
where, how the modules fit together, and the mechanism that keeps every module
replaceable.

The layers are ordered by direction of knowledge: **lower layers know nothing about
upper layers.** An executor knows its provider's wire protocol and one account's
credentials — nothing about routing strategy. The account selector knows pools and
quota state — nothing about HTTP. That one-way dependency rule is the whole secret
to swap-ability.

## The two-stage request path

<diagram data={{
  html: '<div style="display:flex; flex-direction:column; gap:6px">'

    + '<div class="diagram-muted" style="font-size:12px">stage 2 is policy-armored: no model router, cache hint, or escalation result can bypass account eligibility, cooldown, or compliance state.</div>'

<callout tone="decision">Stage 2 owns the final word on everything that touches an account: eligibility (enabled, auth-valid), cooldown, quota reserve, serial cursor, and the compliance floor (permanent-denial identities are never selected). Stage 1 picks *what* to ask; stage 2 picks *whom to ask as*.</callout>

## Serial failover, precisely

<diagram data={{
  html: '<div style="display:grid; grid-template-columns:repeat(4,1fr); gap:8px">'
    + '<div class="diagram-card"><b>ACTIVE (N)</b><br/><small>cursor on account N; all traffic; reserve threshold armed</small></div>'
    + '<div class="diagram-card"><b>LIMIT HIT</b><br/><small>classified 429/usage-cap or quota telemetry &lt; reserve → persist reset+cooldown</small></div>'
    + '<div class="diagram-card"><b>ADVANCE (N+1)</b><br/><small>cursor moves; N+1 becomes active; no flapping back</small></div>'
    + '<div class="diagram-card"><b>FAILBACK</b><br/><small>after N\'s reset + grace → one probe → success → cursor home</small></div>'
    + '</div>'
}} />

Rules that make it deterministic (and testable): never estimate "low tokens" from
local counts — only provider telemetry (headers/usage endpoints) or a classified
limit response moves the cursor. Cursor is persisted, so a restart doesn't reshuffle.
Failback happens once, after reset + grace, via a single probe — not on the next
random request.

## Swappability mechanics (the actual trick)

1. **Every module hides behind a tiny interface we own.** Donor code — CLIProxyAPI
   executors, Bifrost conversions — is adapted at the boundary, never imported
   deep. Replacing Bifrost with another converter touches one adapter file.
2. **Pinned commits + a ledger.** VENDORING.md records donor, commit, paths,
   destination module, license, modifications. Upgrading a donor = bump the pin,
   run the module's golden tests, done. Rebasing the gpt-load baseline is an
   explicit operation (`git merge upstream/main`), never a package update.
3. **One outbound edge.** Only executors speak to the internet. The vault, the
   selector, the scheduler, the UI never make network calls — so a donor with
   phone-home habits is neutered by construction.
4. **State lives in one place.** SQLite + Keychain/libsecret key. Modules can be
   rewritten freely because the contract with reality (the DB schema) is narrow.
