## Trace suitability and limits

The pinned Open-SWE-Traces v1.0 data distribution reports 151,219 trajectories across OpenHands and SWE-agent, generated by MiniMax-M2.5 and Qwen3.5-122B. Its record schema contains the full `messages` conversation (assistant/model and tool turns), `trajectory_id`, source `repo` and `license`, `metadata.teacher_model`, and `resolved` (`1` solved, `0` unsolved, `-1` unavailable). The pinned card describes the data as synthesized/automated and explicitly lists the upstream issue sources. This is a legitimate historical coding-agent trace source with recorded model outputs and per-trajectory quality labels, not a human-authored trace.

For a historical, fixed-model comparison, use only rows from the pinned revision and the same agent scaffold; retain rows whose source-repository SPDX license is MIT, Apache-2.0, BSD-2-Clause, or BSD-3-Clause and whose `resolved` is `0` or `1`. Pair models only on the exact shared `instance_id`; do not infer a shared cohort from aggregate counts. Freeze the sorted paired task IDs and their source revision before analysis. Do not redistribute raw traces or source checkouts in this repository; preserve attribution and each task's source license in any private run manifest.

That historical set is not sufficient to establish the M2 routing result. It has no per-call latency or provider-billed token/cost fields, and one model's later turns follow its own prior answers and tool results. It therefore does not contain counterfactual answers from the alternate model for the same intermediate request prefix. Replaying one model's captured assistant response after Switchyard chooses a different model would be a false routing experiment. Dataset `resolved` labels are the publisher's automated/hybrid outcome labels, not independent re-verification performed by this spike.

For actual routing quality/cost/latency, use the pinned OpenThoughts-TBLite task corpus and acquire new, full agent runs for every arm. The 100 tasks and their verifiers are Apache-2.0 and are the same default corpus used by the pinned Switchyard Harbor runner. Each live arm then supplies genuine per-model responses, verifier outcomes, and provider usage. This avoids substituting static model outputs for missing counterfactuals.

## Reproducible live evaluation protocol

Do not run the workload on a shared Podman VM hosting live services. Runtime execution is blocked pending an isolated host: macOS Podman Machine cannot start a second VM while the existing UAT machine is running, and stopping that machine is not authorized. Obtain a separately provisioned, capacity-checked Podman-capable host or an explicitly approved maintenance window. Until then, the commands below are an acquisition protocol, not authorization to execute. Use the approved runtime's verified Docker-compatible Podman endpoint/Compose adapter; do not start a rootful or host-local Docker daemon as a workaround.

1. In an isolated evaluation checkout, clone Switchyard and detach at the pin:

   ```bash
   git clone https://github.com/NVIDIA-NeMo/Switchyard.git switchyard-spike
   git -C switchyard-spike checkout --detach 9cf6fadfc60bfdf59ee61bf8a14226807c2540bc
   cd switchyard-spike
   uv sync
   ```

2. Check out the pinned Apache-2.0 task corpus outside this repository and prepare its closed-book Harbor export with the pinned runner. Keep generated data and all run outputs outside both source checkouts:

   ```bash
   mkdir -p "$HOME/.cache/demerzel-spike"
   git clone https://huggingface.co/datasets/open-thoughts/OpenThoughts-TBLite "$HOME/.cache/demerzel-spike/OpenThoughts-TBLite"
   git -C "$HOME/.cache/demerzel-spike/OpenThoughts-TBLite" checkout --detach 7b70111339b4af23cece95d63aeec1c705790868
   python benchmark/prepare_harbor_dataset.py \
     --source-dir "$HOME/.cache/demerzel-spike/OpenThoughts-TBLite" \
     --output-dir "$HOME/.cache/demerzel-spike/tblite-closed-book" \
     --overwrite
   ```

   Apply the Harbor patch and verify the prepared dataset manifest as described in the pinned [`benchmark/README.md`](https://raw.githubusercontent.com/NVIDIA-NeMo/Switchyard/9cf6fadfc60bfdf59ee61bf8a14226807c2540bc/benchmark/README.md). Keep the generated dataset digest and manifest for every arm. Use all 100 tasks for reported quality results; the upstream 20-task subset explicitly warns of a ±2–5 percentage-point noise floor and is only suitable for a smoke iteration.

3. Use a single provider account/endpoint and stable model IDs throughout. The pinned Switchyard classifier profile is [`benchmark/server-configs/tb-lite-llm-classifier-opus-kimi-gemini.toml`](https://raw.githubusercontent.com/NVIDIA-NeMo/Switchyard/9cf6fadfc60bfdf59ee61bf8a14226807c2540bc/benchmark/server-configs/tb-lite-llm-classifier-opus-kimi-gemini.toml): Gemini 3.5 Flash judges between Claude Opus 4.7 and Kimi K2.7 Code. Confirm all three IDs are available to the authorized provider account before starting. Provision `OPENROUTER_API_KEY` only through the VM secret mechanism. Keep arms sequential with identical dataset, agent/version pins, reasoning settings, concurrency, timeout and retry policy:

   ```bash
   : "${OPENROUTER_API_KEY:?Provision through the VM secret mechanism before running}"
   RUNS="$HOME/.cache/demerzel-spike/runs"
   DATASET="$HOME/.cache/demerzel-spike/tblite-closed-book"
   mkdir -p "$RUNS"

   # Three repetitions; output directories are unique and every arm uses all 100 tasks.
   for repetition in 1 2 3; do
     bash benchmark/run-baseline.sh --harbor-path "$DATASET" --model anthropic/claude-opus-4.7 \
       --agent codex --reasoning-effort xhigh --n-concurrent 1 --max-retries 0 \
       --foreground --output-dir "$RUNS/fixed-opus-$repetition"
     bash benchmark/run-baseline.sh --harbor-path "$DATASET" --model moonshotai/kimi-k2.7-code \
       --agent codex --reasoning-effort xhigh --n-concurrent 1 --max-retries 0 \
       --foreground --output-dir "$RUNS/fixed-kimi-$repetition"
     bash benchmark/run-baseline.sh --harbor-path "$DATASET" \
       --server-config benchmark/server-configs/tb-lite-llm-classifier-opus-kimi-gemini.toml \
       --model switchyard --agent codex --reasoning-effort xhigh --n-concurrent 1 --max-retries 0 \
       --foreground --output-dir "$RUNS/switchyard-classifier-$repetition"
   done
   ```

   Do not put credentials in shell history, a file, or a command argument. Pre-approve the paid-provider spend for the planned repetitions.

4. Add the non-LLM simple-rule arm using the documented `stage_router` with `picker = "efficient_first"`, `confidence_threshold = 0.5`, and **no classifier**. It routes from tool-result history only. Continue in the same shell as step 3 and write this config to `$RUNS/stage.toml`, outside the product checkout:

   ```bash
   cat > "$RUNS/stage.toml" <<'TOML'
   schema_version = 1

   [llm_clients.openrouter]
   format = "openai_chat"
   base_url = "https://openrouter.ai/api/v1"
   api_key_env = "OPENROUTER_API_KEY"

   [targets.strong]
   id = "anthropic/claude-opus-4.7"
   llm_client = "openrouter"

   [targets.weak]
   id = "moonshotai/kimi-k2.7-code"
   llm_client = "openrouter"

   [routes.stage]
   id = "stage"
   type = "stage_router"
   capable_target = "strong"
   efficient_target = "weak"
   picker = "efficient_first"
   confidence_threshold = 0.5
   TOML

   for repetition in 1 2 3; do
     bash benchmark/run-baseline.sh --harbor-path "$DATASET" --server-config "$RUNS/stage.toml" \
       --model stage --agent codex --reasoning-effort xhigh --n-concurrent 1 --max-retries 0 \
       --foreground --output-dir "$RUNS/stage-rule-$repetition"
   done
   ```

   The pinned [stage-router guide](https://raw.githubusercontent.com/NVIDIA-NeMo/Switchyard/9cf6fadfc60bfdf59ee61bf8a14226807c2540bc/docs/routing_algorithms/stage_router_routing.md) documents this TOML shape. Keep this separate from the classifier arm: it is the deterministic simple-rule baseline, not a second classifier result.

5. Measure selector overhead separately from task quality with the pinned [`benchmark_routing_algorithms.py` soak procedure](https://raw.githubusercontent.com/NVIDIA-NeMo/Switchyard/9cf6fadfc60bfdf59ee61bf8a14226807c2540bc/docs/operations/soak_test.md). Continue in the same shell as step 3 to write `$RUNS/overhead.toml`, then use separate terminals in the **approved isolated Podman runtime**, not shared UAT. Use an overhead-only config with both completion targets set to Claude Opus 4.7, Gemini 3.5 Flash as classifier, and both stage and classifier routes:

   ```bash
   cat > "$RUNS/overhead.toml" <<'TOML'
   schema_version = 1

   [llm_clients.openrouter]
   format = "openai_chat"
   base_url = "https://openrouter.ai/api/v1"
   api_key_env = "OPENROUTER_API_KEY"

   [targets.strong]
   id = "anthropic/claude-opus-4.7"
   llm_client = "openrouter"

   [targets.weak]
   id = "anthropic/claude-opus-4.7"
   llm_client = "openrouter"

   [targets.classifier]
   id = "google/gemini-3.5-flash"
   llm_client = "openrouter"

   [routes.stage]
   id = "stage"
   type = "stage_router"
   capable_target = "strong"
   efficient_target = "weak"
   picker = "efficient_first"
   confidence_threshold = 0.5

   [routes.switchyard]
   id = "switchyard"
   type = "llm_classifier"
   classifier_target = "classifier"
   strong_target = "strong"
   weak_target = "weak"
   base_threshold = 0.5
   threshold_step = 0.0
   classify_trigger = "new_session"
   message_hash_fallback = true
   TOML
   ```

   In terminal A, from the pinned Switchyard checkout on the approved isolated Podman runtime, build and start the server; leave it running and wait for `/health` to return 200:

   ```bash
   RUNS="$HOME/.cache/demerzel-spike/runs"
   : "${OPENROUTER_API_KEY:?Provision through the VM secret mechanism before running}"
   cargo build --release -p switchyard-server
   target/release/switchyard-server --config "$RUNS/overhead.toml" \
     --host 127.0.0.1 --port 4000
   ```

   In terminal B, from the same pinned checkout and with `OPENROUTER_API_KEY` provisioned through the VM secret mechanism, compare direct OpenRouter with the two local route IDs:

   ```bash
   RUNS="$HOME/.cache/demerzel-spike/runs"
   : "${OPENROUTER_API_KEY:?Provision through the VM secret mechanism before running}"
   curl -fsS http://127.0.0.1:4000/health >/dev/null
   python3.12 scripts/benchmark_routing_algorithms.py \
     --base-url http://127.0.0.1:4000 \
     --direct-base-url https://openrouter.ai/api/v1 \
     --direct-api-key-env OPENROUTER_API_KEY \
     --direct-model anthropic/claude-opus-4.7 \
     --model stage=stage --model classifier=switchyard \
     --concurrency 4 --request-count 1000 \
     --scenario-set standard --load-profile fixed --profile-runs 3 \
     --backend-label "OpenRouter Opus 4.7 same-target overhead"
   ```

   This holds the selected completion model constant while still charging classifier latency/cost. Use the same request/session manifest, backend deployment, model and generation settings for direct and routed arms. Retain each raw per-run AIPerf export and routing statistics. The pinned Markdown report surfaces request-latency p50 and TTFT p50/p99, not request p95; derive p95 from the raw export, and treat the gate as unmeasured if that export lacks p95 samples. Run at least 1,000 measured requests per arm for each of three independent runs in a dedicated low-contention window. Do not use mock-backend latency as evidence for the real-provider gate. This paid workload requires a pre-approved spend limit.

   Save each task arm's `run_manifest.json`, Harbor `result.json`, task `trajectory.json` files, `server_metrics_final.prom`, and `routing_stats_final.json`. The pinned [benchmark dataset guide](https://raw.githubusercontent.com/NVIDIA-NeMo/Switchyard/9cf6fadfc60bfdf59ee61bf8a14226807c2540bc/benchmark/DATASETS.md) names these artifacts. Treat traces/logs as potentially sensitive; keep them private, redact secrets, and do not commit run outputs.

   The task runner's Docker Compose calls must reach only the approved isolated Podman runtime through its verified compatibility endpoint. The overhead server and AIPerf process also run there; the direct-provider URL is the only model API egress. Shared UAT engines are excluded until an explicitly approved maintenance window.



## Metrics and acceptance gates

Report each arm separately and report paired deltas against both fixed-model baselines. Use the complete fixed 100-task cohort and all three repetitions; include the numerator/denominator, run failures, and uncertainty interval, not only a rounded percentage.

- **Quality:** `verified tasks passed / 100`. A task counts as passed only when Harbor's task verifier says it passed. Report all infrastructure/agent failures separately; do not silently drop them or count them as solved. For the historical trace audit only, use `resolved` and exclude `-1`.
- **Cost:** sum actual provider-billed input/output/cache charges for every request in the task, including classifier calls, retries, and failed attempts; report total cost and cost per verified pass. Record provider, model ID, pricing source and retrieval timestamp. If actual billing/usage cannot be obtained, mark cost unavailable (or explicitly label an estimate); do not substitute text-length estimates for provider usage.
- **Task latency:** Harbor task wall-clock duration from agent start through verifier completion; report p50/p95 and per-task values for each arm.
- **Selector overhead:** for the same deterministic AIPerf request/session manifest, calculate `r = (p95(L_routed) - p95(L_direct)) / p95(L_direct)` for each routed strategy, where `L_direct` uses the same provider, completion model, generation settings and request inputs. Include classifier work in routed latency. The gate is `r <= 0.05`; also report absolute added milliseconds, request TTFT, classifier-call latency and provider cost. Use raw per-run samples/quantiles and confidence intervals; do not infer p95 from p50/p99 or compare runs with different inputs.
- **Decision:** the Switchyard classifier arm must improve the cost/quality frontier over both fixed-model and the simple-rule arm without a material quality regression, and meet the p95 overhead gate. The authorized product decision remains with the parent/CTO; no NVIDIA savings or published score is an acceptance result for Demerzel.

## Product boundary and fallback requirement

This spike runs Switchyard only as an external evaluation oracle. It does not alter Demerzel's runtime or establish a production dependency. In any future native stage-1 implementation, the model selector can return only a model from the **served-model set computed from stage-2-eligible accounts**. Stage 2 still owns account eligibility, compliance, cooldown, quota and serial failover; a model-selection result cannot choose or bypass an account.

If selector evaluation errors, times out, returns an invalid/unavailable model, or yields no eligible model, fall back to the configured fixed model **only after confirming that model has an eligible stage-2 account**. Then run the normal stage-2 selector. If that fallback is not eligible, fail closed with the existing no-eligible-account behavior; do not dispatch directly to an upstream or let Switchyard pick an account. Provider/account failures continue through existing stage-2 policy. These are required contracts for a later Demerzel implementation, not behavior exercised by this external spike.

## Blocker and evidence state (2026-09-24)

- **Pinned source/license:** verified from NVIDIA's primary GitHub repository API and the immutable commit's LICENSE. The commit is `9cf6fadfc60bfdf59ee61bf8a14226807c2540bc`, Apache-2.0.
- **Trace candidate:** the pinned CC-BY-4.0 Open-SWE-Traces snapshot contains actual generated model/tool messages and per-trajectory outcome labels. It cannot supply per-prefix counterfactual responses, provider cost or latency. The pinned Apache-2.0 OpenThoughts-TBLite corpus supplies a reproducible, verifier-backed 100-task live cohort, but no recorded model outputs until the arms run.
- **Missing prerequisites:** authorized provider credentials/availability for the three pinned model IDs, live provider responses and usage/billing metadata were not supplied. Runtime execution also requires an isolated Podman-capable host; the shared UAT VM cannot be mutated, and macOS cannot start another Podman Machine concurrently. Obtain a separate host or explicitly approved maintenance window before running; do not use or stop a live UAT engine unilaterally. No outbound paid requests were attempted.
- **No benchmark results:** fixed-model, stage-rule and classifier arms were not run; there are no observed quality, cost, latency or selector-overhead numbers. The ≤5% p95 gate is therefore unproven. Parent execution of the protocol above is required before M2 acceptance or an M5 decision.
